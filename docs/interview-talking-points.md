# Eight interview talking points

1. **One result owner.** React stores a completed result snapshot once. The sidebar, map and details cannot accidentally show separate searches. Aborting requests prevents stale replies from winning.
2. **Hard rules before similarity.** SQL applies budget, capacity and amenities first. Embeddings only reorder eligible stays, so a high similarity score cannot excuse a broken requirement.
3. **AI has a small job.** One compatible endpoint translates language into validated filters. A strict deadline and one repair attempt keep failure bounded; the disclosed keyword parser keeps the demo useful without a key.
4. **Explain only what we know.** A template uses returned rows for counts, prices and neighborhoods. It is less conversational, but cannot invent listing benefits.
5. **Reuse rendering work.** Four shared model scenes serve hundreds of instances. Stable per-listing colors add variety without multiplying downloads or GPU scene objects. Pixel caps and declutter reduce visual work.
6. **Motion follows user intent.** Selecting a stay flies to it; removing it through filters closes details without resetting the camera. Reduced-motion settings disable animated travel and panel motion.
7. **Keep the prototype honest.** Records are synthetic and illustrations are labeled. Demo responses are saved JSON, not presented as live model output. Model and map licenses are documented and map credits remain visible.
8. **Simple storage has boundaries.** SQLite, an in-memory cache and an IP limiter are easy locally. Multiple replicas would require shared storage/rate limiting; a free host also needs a plan for sleep, memory and ephemeral disk.
